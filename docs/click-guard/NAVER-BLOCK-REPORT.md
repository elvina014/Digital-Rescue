### 동작 요약
- **등록:** ADMIN 확인 → IPv4 확인 → 화이트리스트면 거부 → 네이버 목록 조회 → 이미 있으면 등록하지 않고 ERP 표시만 맞춤(`[CG]`면 API 등록, 그 외·와일드카드 대역이면 수동 등록) → 500개 이상이면 "슬롯 부족" → 등록(메모 `[CG] YYMMDD <메모 앞 13자>`) → 성공 시에만 ERP 기록 → 모든 결과를 `cg_block_log`에 기록.
- **해제:** 네이버 목록에서 그 IP를 찾아 메모가 `[CG]`로 시작할 때만 삭제. 수동 등록분·와일드카드 대역은 "네이버에서 직접 등록한 항목이라 ERP에서 해제할 수 없습니다". 네이버에 이미 없으면 ERP 표시만 해제.
- **현황 확인:** 네이버 등록 수 / 600, `[CG]` 수, 불일치 목록 2종. 읽기만 하고 고치지 않는다.
- **화면:** 등록·해제는 낙관적 UI 없이 서버 응답 후 반영. 처리 중 버튼 비활성, 성공/실패 토스트. 다중 선택 일괄 등록은 없다.

### 요청서와 다르게 한 것 (승인된 결정 + 구현 중 판단)
1. 네이버 메모 형식: 25자 제한 때문에 `[CG] YYMMDD <메모 앞 13자>`. 관리자명·메모 전문은 `cg_block_log.detail`과 `cg_ip_marks.memo`에 있다. (승인 1)
2. 함수 권한: "REVOKE PUBLIC/anon" 대신 R10 방식(EXECUTE 유지, 함수 안에서 ADMIN이 아니면 거부). (승인 2)
3. IPv6 거부, 수동 와일드카드 대역에 포함되면 등록하지 않음. (승인 3, 4)
4. `cg_mark_naver_registered`에 네 번째 인자 `p_source('api'|'manual', 기본 'api')`를 추가했다. 요청서 3단계 3번의 "수동 등록분이면 manual로 표시"와 [수동 표시] 버튼에 필요하다.
5. [수동 표시]는 기존 `cg_mark_ip` 대신 `cg_mark_naver_registered(…, 'manual')`를 부른다. 기존 함수는 수정하지 않았다(추가만).
6. `cg_mark_naver_unregistered`는 등록완료 표시 행을 지워 미처리로 되돌린다. 이력은 `cg_block_log`에 남는다.
7. API로 등록된 IP는 [관찰]/[정상]/[표시 해제]로 표시만 바꿀 수 없게 했다(`markIpAction`에서 거부, 화면에서는 [차단 해제]만 표시). 표시만 바뀌고 네이버 차단이 남는 것을 막기 위해서다.
8. 등록 창의 "현재 슬롯 사용량"은 창을 열 때 네이버 목록을 한 번 읽는다(감사 로그는 남기지 않음). [네이버 등록 현황 확인]은 `sync` 로그를 남긴다.
9. `server-only` 패키지를 의존성에 추가했다(`package.json`).

### 모킹 테스트가 확인한 것 (`tests/naver-sa/naver-sa.test.mjs`)
- 서명: `timestamp.METHOD.path` → HMAC-SHA256 → Base64. 문서 예시에는 비밀키가 없어 정답값 대신 Node `crypto`로 따로 계산한 값과 비교했다. 쿼리스트링을 넣으면 다른 서명이 되는 것도 확인.
- 요청: 주소, 메서드, 헤더 4종, 등록 본문(`filterIp`, `memo`), 삭제 경로.
- 성공 / 이미 존재(`[CG]`) / 이미 존재(수동) / 와일드카드 대역 / 슬롯 부족 / 화이트리스트·IPv6·빈 메모 거부.
- 네트워크 타임아웃, 인증 실패(403): 목록 단계와 등록 단계 모두에서 **DB가 바뀌지 않고** 실패 로그만 남는다.
- 네이버 등록은 됐는데 ERP 기록이 실패한 경우: 오류 반환 + 로그, 다시 누르면 새로 등록하지 않고 맞춰진다.
- 해제: `[CG]`만 삭제, 수동 항목 거부, 실패 시 DB 불변, 네이버에 없으면 ERP 표시만 해제.
- 현황: 사용량·불일치 목록만 반환하고 아무것도 고치지 않는다.

### 로컬 화면에서 확인한 것 (네이버 키 없이)
- 새 버튼과 안내 문구, 등록 창(IP·점수·사유·공용 IP 경고·메모 필수·슬롯 사용량), 메모가 비면 등록 버튼 비활성.
- 키가 없으면 등록·해제·현황 확인이 "네이버 API 키가 설정되지 않았습니다"로 끝나고 DB는 그대로, `cg_block_log`에 fail 기록.
- 처리 중 버튼 비활성("등록 중…"), 응답 후 토스트, 실패 시 창 유지.
- [수동 표시] → "수동 등록" 배지 + 안내문 + [표시 해제]. API 등록 행(로컬에 직접 넣은 행) → "네이버 등록됨(API)" 배지 + [차단 해제].

### 확인하지 못한 것
- **실제 네이버 응답.** 등록 성공 화면(토스트, 배지 전환), 슬롯 사용량 숫자, 현황 목록은 실제 키가 있어야 나온다. 흐름은 모킹 테스트로만 확인했다.
- 네이버 문서에 없는 사항: IPv6, 와일드카드 형식, 최대 600개, 오류 본문 형식, 등록 응답이 200인지 201인지, 등록 응답에 `ipFilterId`가 오는지. 응답에 ID가 없으면 목록을 다시 읽어 찾도록 해 두었다.
- 인증 실패 시 네이버가 실제로 401/403을 주는지(다른 상태면 "네이버 API 호출에 실패했습니다"로 표시되고 원문은 로그에 남는다).

### 기존 실패 1건 (이번 작업과 같은 원인으로 숫자만 늘어남)
`vector_integration.test.sql` #20은 이전부터 실패하던 테스트다(identity 컬럼이 있는 테이블의 UPDATE가 42501 대신 428C9를 돌려줌). `cg_block_log`도 identity 컬럼을 써서 이 테스트에 걸리는 테이블이 하나 늘었다(현재 4개). 권한 자체는 막혀 있고(신규 pgTAP에서 직접 INSERT가 42501로 거부되는 것을 확인) 이 테스트의 기대값 문제다.

   2. 본인 테스트용 IP 1개를 [네이버에 차단 등록] → 검색광고센터 광고노출제한 관리에 `[CG] …` 메모로 보이는지.

6. 문제가 생기면: 환경변수 3개를 지우면 네이버 호출이 멈추고 [수동 표시]만 쓸 수 있다. DB 되돌리기는 `rollback-naver-block.sql`(로그와 네이버 항목 ID가 사라진다).

## 개인정보처리방침
이 기능은 이미 수집·고지한 접속 IP를 네이버(광고 플랫폼)에 광고노출 제한용으로 전송한다. 현재 방침 1조의 목적("비정상적인 반복 클릭을 확인하고 대응")에는 들어 있지만, 5조(위탁)·4조(제3자 제공)에 네이버가 없다. 방침에 반영할지는 대표 확인이 필요하다(이번 작업 범위 밖이라 수정하지 않았다).
