# 회귀 점검 체크리스트 — Repair Intelligence 출시 (Phase 0.5 ~ 9)

Brad가 직접 수행하는 수동 점검표. 형식: **동작 → 기대 결과**, 끝나면 체크.
순서: 0 준비 → 1 기존 업무(역할별) → 2 신규 기능(역할별) → 3 정리 → 4 병합 후 운영 확인.
근거 문서: `../04-final-release-plan.md` (§2.2 창 위험, §3 Preview 전략, §3.4 테스트 데이터·정리), `release-runbook.md` (단계 4~6).

### 0.2 규칙 (반드시)

- 입력하는 이름은 모두 **`[테스트]`로 시작**: 고객명, 모델·보드·부품 규격명, 별칭, 재고 품목명, 메모.
  형식이 고정된 코드는 예외: 보관 위치 `TEST-01`(설명 `[테스트]`), 증상 코드 `TEST.PREVIEW`(이름 `[테스트] …`).
- 테스트 접수건은 `is_test`여야 한다. 체크박스 "테스트 접수입니다"는 **ADMIN/MANAGER의 신규 접수 화면에만** 있고, "테스트로 표시" 토글은 **ADMIN 전용**이다.
  RECEPTION·대고객 폼으로 만든 건은 ADMIN이 **바로, 승인 전에** "테스트로 표시" (KI-9: 승인 후에는 바뀌지 않음).
- `is_test` 접수건은 **ADMIN/MANAGER 외 역할의 접수건 목록에 나오지 않는다** (`tickets/page.tsx`). 다른 역할은 접수건 상세 주소(`/tickets/<id>`)를 직접 열어 점검한다 — 주소를 0.4에 같이 기록.
- **실제 재고를 테스트 접수건에 출고하지 않는다.** 1-6-1에서 만든 `[테스트]` 재고 품목만 쓴다.
- 고객 사진·실제 고객 정보 사용 금지. AI 후보는 `[테스트]` 대상에만 승인.
- 구매 가드·수리 기록 게이트 플래그는 **OFF 유지** (선택 항목 2-6-9만 예외, 업무시간 외, 즉시 OFF 복구).
- 실제 라벨을 Preview에서 인쇄하지 않는다 (QR에 Preview 주소가 들어감). 인쇄 미리보기 / PDF까지만.
- CMS·뉴스는 **저장하지 않는다** (대고객 사이트에 바로 노출됨).
- 운영 SQL Editor에서 **"Run as role" 금지** (KI-8, 0.6a 적용 전 기준이며 적용 후에도 습관적으로 금지).

## 1. 기존 업무 (Preview) — 역할별

> 하나의 테스트 접수건을 따라가며 점검한다. 괄호 안 번호는 선행 항목.

### 1-1. RECEPTION (접수처)

- [ ] 1-1-1 사이드바 확인 → 대시보드, 신규 접수, 접수건 목록, 부품·기기 검색, 라벨 조회만 보임. 재고 관리·통계·기기 마스터·직원 관리 없음.
- [ ] 1-1-2 신규 접수: 고객 `[테스트]홍길동`, 전화 `010-0000-0000`, 기기 노트북 / 브랜드 `[테스트]` / 모델 `[테스트] PREVIEW-MODEL-01`, 증상 입력 → 저장 → 접수번호 발급. RECEPTION 화면에는 "테스트 접수입니다" 체크박스가 **없음**(기존 동작). (번호·주소를 0.4에 기록)
- [ ] 1-1-2a ADMIN: 그 접수건 상세 → **"테스트로 표시"** → 노란 테스트 표시. RECEPTION 목록에서는 이제 보이지 않음(기존 동작) → 이후 RECEPTION은 상세 주소로 연다.
- [ ] 1-1-2b MANAGER: 신규 접수에서 "테스트 접수입니다" 체크 → 두 번째 테스트 접수건 생성 (1-4-9 취소용), 세 번째 (1-8 EXPERT_REPAIR 배정용). (기록)
- [ ] 1-1-3 접수건 사진 1장 업로드 → 썸네일 표시 (WebP 변환).
- [ ] 1-1-4 담당 기사 배정 (TECHNICIAN 계정) → 상태 ASSIGNED, 로그 한 줄.
- [ ] 1-1-5 입고 처리 → 상태 RECEIVED, 입고 일시 표시.
- [ ] 1-1-6 접수건 목록 검색창에 실제 고객 이름 일부 입력 → 기존과 같이 검색됨. (MANAGER로 필터 "테스트 포함" + `[테스트]홍` → 테스트 건 검색됨)
- [ ] 1-1-7 `/stats` 주소 직접 입력 → `/dashboard`로 이동 (통계 권한 없음).
- [ ] 1-1-8 (알려진 문제 KI-10) NEW 상태 테스트 접수건에서 "접수 취소" → 기존과 같이 실패 메시지 "new row violates row-level security…" (변경 없음 확인용. 성공하면 기록).

- [ ] 1-4-4 승인된 자재 줄 "출고 취소 요청" → 취소요청 상태, 수량 변화 없음.
