## 3. 이미지 다운로드 (요청 2)

### 방식
브라우저에서 **Canvas로 라벨을 직접 그려 PNG로 저장**한다 (서버 부하·새 의존성 없음).

- 해상도 **300 DPI** → 555 × 318 px (47 × 26.9 mm).
- PNG에 **pHYs(300 DPI) 메타데이터**를 기록 → 폼텍 프로그램에 넣었을 때 실제 크기(47 × 26.9 mm)로 인식되도록 한다.
- QR은 `qrcode`의 `toCanvas`로 같은 URL(`/scan/<코드>`)을 그린다. 텍스트·크기·위치는 §2 표와 동일한 수치(mm → px 변환)를 공용 상수로 둬서 인쇄 화면과 이미지가 같게 보이도록 한다.
- 배경 흰색(투명 아님), 테두리 없음.

### UI (`print/page.tsx`)
- 상단 버튼: `인쇄` 옆에 **`이미지 저장 (전체)`** — 라벨마다 `P-00012.png` 파일을 차례로 다운로드.
  - 여러 장 다운로드 시 브라우저가 처음 한 번 "여러 파일 다운로드 허용"을 물을 수 있다 (안내 문구 표시).
- 각 라벨 미리보기 아래 **`PNG`** 버튼 — 그 라벨 1장만 저장.

### 파일
- 신규 `print/labelLayout.ts` — 크기·글자 크기 공용 상수.
- 신규 `print/labelImage.ts` — Canvas 렌더 + PNG(pHYs) 생성 (클라이언트 전용).
- 신규 `print/DownloadButtons.tsx` — 전체/개별 저장 버튼 (`"use client"`).
- 수정 `print/LabelSheet.tsx`, `print/page.tsx`.
  - 이미지 생성을 위해 QR URL(`scanUrl`)을 클라이언트에 함께 넘긴다 (`PrintLabel.scanUrl` 추가).

## 4. 검토: ERP에서 지정 칸에 직접 인쇄 (요청 3)

### 결론: **가능하다. 작업량은 작음~중간(코드 반나절 + 실제 용지 보정 테스트).**

### 구현 방식
1. `/labels/print`에 **용지 방식 선택**: `감열 라벨(1장=1페이지)` / `폼텍 3102 (A4 40칸)`.
2. 폼텍 모드에서는 A4 미리보기에 4열 × 10행 칸을 그리고, **사용할 칸을 클릭으로 선택**(이미 쓴 칸은 비워 둠). 선택한 칸 순서대로 라벨 배치, 칸이 모자라면 다음 A4 페이지.
3. 인쇄 CSS: `@page { size: A4; margin: 0 }`, 각 칸을 mm 단위 절대 위치로 배치.
4. **프린터 보정값**(가로·세로 mm 오프셋)을 입력 → 브라우저 `localStorage`에 저장 (PC·프린터마다 다르므로 DB에 두지 않음).

### 규격(확인 필요)
- 확인된 값: A4, 40칸(4 × 10), 칸 47 × 26.9 mm.
- **칸 사이 간격·여백은 공개 자료에서 확인하지 못함.** 간격 0이라 가정하면 좌우 11 mm, 상하 14.05 mm.
  → 구현 시 Brad가 실제 라벨지를 자로 재서 (왼쪽 여백, 위쪽 여백, 가로·세로 간격) 4개 값을 주거나, 시험 인쇄 후 보정값으로 맞춘다.

### 위험·한계
- 인쇄 창에서 **배율 100%, 여백 없음**을 매번 지켜야 한다 (아니면 칸이 밀림). 크롬은 마지막 설정을 기억하는 편이지만 보장되지 않음.
- 프린터 급지 오차 ±0.5~1 mm는 피할 수 없음. 라벨 안쪽 여백 1.5 mm로 대부분 흡수.
- 프린터 인쇄 불가 영역(보통 3~5 mm)은 여백(11/14 mm) 안이라 문제없음.

### 예상 작업량
| 항목 | 규모 |
|---|---|
| 용지 방식 선택 + A4 칸 선택 UI | 컴포넌트 1개, 약 120줄 |
| A4 배치 인쇄 CSS + 다중 페이지 | 약 50줄 |
| 보정값 입력·저장 | 약 40줄 |
| 실제 라벨지 시험 인쇄·보정 | Brad 참여 필요 (1~2회) |
