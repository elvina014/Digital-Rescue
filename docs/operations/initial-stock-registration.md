# 매장 재고 첫 등록 안내 (직원용)

작성 2026-11-27 · 기준 코드 `main` @ `83cfc16` · Repair Intelligence 운영 반영(Phase 0.5 – 9) 기준
갱신 2026-11-27 · §6.5 매장 보관 기기 Donor 등록 추가 (Phase 4.1, `feat/repair-intelligence` @ `60cebe4`) — **운영 서버에 Phase 4.1이 적용된 뒤부터** 화면에 보입니다.

이 문서는 매장에 쌓여 있는 부품·기기를 ERP에 **처음** 등록하는 방법을 설명합니다.
모든 화면은 직원용 주소 **login.digital-rescue.com** 왼쪽 메뉴에 있습니다.
화면 이름·버튼 이름은 실제 화면에 보이는 글자 그대로 적었습니다.

> ⚠ 표시는 "요청하신 기능이 아직 화면에 없어서 다른 방법으로 해야 하는 부분"입니다. 이유와 대안은 문서 끝 **검토 사항**에 정리했습니다.

1. 관리자: 보관 위치 만들기 (§1)
2. 관리자: 재고 분류 정리 (§3-1), 자주 쓰는 모델·보드 등록 (§2)
3. 관리자·팀장: 신품 재고 등록 → 라벨 인쇄 → 붙이기 → 위치 지정 (§3)

- **고객 이름·전화번호·주소는 어떤 칸에도 적지 마세요.** (메모, 모델명, 사진 포함)
- 매입가를 모르면 기초견적은 **0원**으로 둡니다 (§8).
- 같은 물건을 두 번 등록하지 마세요. 등록 전에 재고 관리 화면에서 먼저 검색하세요.
- 실수로 잘못 등록했으면 **직접 고치려 하지 말고 관리자에게 알리세요** (검토 사항 C).

## 1. 보관 위치 등록과 위치 라벨

### 1.1 보관 위치 만들기 (관리자)

메뉴 **보관 위치 관리** (`/inventory/locations`)

1. 위쪽 입력칸 **위치 코드**에 코드를 적습니다. 예: `A-01-04` (구역 A · 랙 01 · 칸 04), `DONOR-C07`
   - 영문 대문자·숫자와 `-`만 쓸 수 있고 20자 이내입니다. 소문자로 적어도 대문자로 바뀝니다.
2. **설명 (선택)** 칸에 쉬운 설명을 적습니다 (100자 이내). 예: "작업대 뒤 2단 선반"
3. **추가** 버튼을 누릅니다.

- 코드는 **등록 후 바꿀 수 없습니다.** 신중하게 정하세요.
- 위치는 삭제할 수 없고, 쓰지 않으면 상태 칸의 **사용 중 · 중지** 버튼으로 중지합니다 (**중지됨 · 다시 사용**으로 되살림).
- 설명은 표에서 칸을 눌러 바로 고칠 수 있습니다.
- 표의 **보관 중** 숫자 = 그 위치에 지정된 재고 행 + Donor 기기 수.

### 1.2 위치 QR 라벨 ⚠

**현재 보관 위치 자체의 QR 라벨을 인쇄하는 기능은 없습니다.** 라벨 인쇄 화면에는 "재고"와 "Donor 기기" 두 종류만 있습니다.
그동안은 다음처럼 하세요.

- 선반·칸에는 위치 코드(예: `A-01-04`)를 **글자로** 적은 표찰을 붙입니다.
- 재고 라벨과 Donor 라벨에는 지정된 위치 코드가 **작은 글씨로 함께 인쇄**됩니다 (위치를 먼저 지정하고 인쇄한 경우).
- 라벨 조회 화면에 위치 코드를 넣어도 조회되지 않습니다 (재고 `P-`, Donor `D-` 코드만 조회됨).

### 1.3 재고·Donor에 위치 지정하기 (관리자·팀장)

위치 지정은 **라벨 조회** 화면에서 한 건씩 합니다.

1. 메뉴 **라벨 조회** → 라벨 QR을 휴대폰 카메라로 찍거나, 코드(예: `P-00012`)를 입력하고 **조회**
2. 결과 화면 아래 **현재 위치** 옆 목록에서 위치를 고르고 **보관 위치 변경**
3. 위치를 빼려면 목록에서 **위치 해제**를 고르고 **보관 위치 변경**

- 목록에는 "사용 중"인 위치만 나옵니다.
- 담당기사 등 다른 역할은 위치를 볼 수만 있습니다.

## 2. 기기 마스터 (모델 · 변형 · 보드 번호)

호환 부품을 찾으려면 "어떤 기기인가"가 표준 이름으로 등록되어 있어야 합니다.

### 2.1 관리자 화면에서 등록

메뉴 **기기 마스터** (관리자 전용). 위쪽 탭: 모델 매핑 / 모델 목록 / 보드 목록 / 증상 코드 / 부품 규격 / 재고 연결 / AI 후보

**모델 등록** — 탭 **모델 목록**
1. **+ 새 모델** → 칸 3개 입력
   - 브랜드 (필수, 50자 이내, 예: LG)
   - 모델명 (필수, 100자 이내, 예: 그램 15 15Z90T)
   - 변형 (선택, 예: OLED)
2. **등록**. 이미 있는 모델이면 새로 만들지 않고 그 모델이 선택됩니다.
3. 왼쪽 목록에서 모델을 누르면 오른쪽에서 고칠 수 있습니다.
   - 모델명, 기기 종류, 출시 연도, 메모 → **저장**
   - **변형**: "변형 추가 (예: OLED, LCD 터치)" 칸에 입력 → **추가**
   - **별칭**: "별칭 추가 (예: 15Z90T-GA5HK)" 칸에 입력 → **추가** (라벨에 적힌 정식 품번을 별칭으로 넣어 두면 검색이 잘 됩니다)
   - **연결된 메인보드**: 아래 보드 검색칸에서 보드를 고르면 연결됩니다

**보드 번호 등록** — 탭 **보드 목록**
1. **새 보드** 줄에 보드 번호(필수, 예: `LA-K091P`)와 제조사(예: Compal) 입력
2. **등록**

> 보드는 관리자만 등록할 수 있습니다. 다른 직원이 보드 검색에서 못 찾으면 "보드 등록은 관리자에게 요청해 주세요"라고 나옵니다.

### 2.2 모델 선택기에서 즉석 등록 (고객서비스 제외 전 직원)

"표준 모델"을 고르는 칸(신규 접수, 부품·기기 검색, Donor 상세, AI 사진 인식 등)에서:

1. "모델명·별칭으로 검색 (예: 15Z90T, 그램)" 칸에 입력
2. 원하는 모델이 없으면 목록 맨 아래 **+ 새 모델 등록**
3. 브랜드 · 모델명 (필수) · 변형 (선택) 입력 → **등록**
4. 안내 문구 확인
   - "새 모델이 등록되었습니다." (관리자)
   - "새 모델이 등록되었습니다. (관리자 검토 대기)" (관리자 외)
   - "이미 등록된 모델이 있어 해당 모델을 선택했습니다."

- 모델을 고르면 옆에 **변형 선택** 목록이 나옵니다. 모르면 "변형 선택 안 함"으로 둡니다.
- 보드 선택기에는 즉석 등록이 없습니다 (관리자만 보드 등록).

## 3. 신품 표준 부품 등록 (4단계) + 품목 단위 라벨

재고는 **카테고리 → 사양 → 제품 → 재고 품목** 4단계입니다.
예: 카테고리 `RAM` → 사양 `DDR4 노트북` → 제품 `삼성` → 품목(용량 `8GB`, 신품, 수량 5)

### 3-1. 분류 만들기 (관리자) — 1~3단계

메뉴 **재고 분류 설정** (`/inventory/settings`)

- 화면 아래에 **카테고리 / 사양 / 제품** 3칸이 있습니다.
- 카테고리를 누르면 그 카테고리의 사양이, 사양을 누르면 그 사양의 제품이 보입니다.
- 각 칸의 **+ 추가** → 입력창에 이름을 넣습니다. 콤마(,) 또는 줄바꿈으로 여러 개를 한꺼번에 붙여넣을 수 있습니다.
- 이름 옆 **수정** / **삭제**. 카테고리를 삭제하면 하위 사양·제품도 함께 삭제됩니다 (재고가 남아 있는 분류는 삭제되지 않습니다).

### 3-2. 재고 품목 등록 (관리자·팀장) — 4단계

메뉴 **재고 관리** → 오른쪽 위 **+ 신규 등록** (화면 제목 "신규 재고 등록")

| 칸 | 필수 | 설명 |
| --- | :-: | --- |
| 카테고리 | ● | 목록에서 선택 |
| 사양 | ● | 카테고리를 먼저 골라야 선택 가능 |
| 제품명 | ● | 사양을 먼저 골라야 선택 가능 |
| 용량 / 인치수 | | 예: 8GB, 256GB, 15.6인치 |
| 상태 | ● | 신품 / 중고품 (처음 열면 "중고품"이 선택되어 있으니 신품이면 꼭 바꾸세요) |
| 수량 | ● | 0 이상 |
| 기초견적 (원) | ● | 0 이상. 모르면 0 (§8) |

**재고 등록**을 누르면 재고 관리 목록으로 돌아갑니다.

- 카테고리·사양·제품명·용량·상태가 모두 같은 품목이 이미 있으면 "이미 같은 이름의 재고 리스트가 존재합니다…"가 나오며 등록되지 않습니다. 이때는 새로 만들지 말고 관리자에게 **수량 수정**을 요청하세요.
- 목록에 원하는 분류가 없으면 관리자에게 §3-1을 요청하세요.
- 등록하면 품목마다 라벨 코드 `P-00001` 형식이 자동으로 붙습니다 (재고 관리 목록에 표시).
- 이 화면에는 보관 위치·부품 규격 칸이 없습니다. 위치는 §1.3, 부품 규격 연결은 §4.3에서 합니다.

### 3-3. 라벨 인쇄 (관리자·팀장) — 신품은 품목(행)당 1장

메뉴 **라벨 인쇄**

1. 위쪽 **재고** 탭 (Donor는 **Donor 기기** 탭). **최근 7일 등록**을 누르면 최근 등록분만 보입니다.
2. "코드·품목·위치 검색" 칸으로 거른 뒤, 인쇄할 줄의 체크박스를 선택 (맨 위 체크박스 = 보이는 것 전체 선택)
3. **선택 라벨 인쇄 (N)** → 미리보기 화면 → **인쇄**
4. 인쇄 창에서 **여백 '없음', 배율 100%** 로 설정. 라벨 크기 50 × 30 mm, 1장 = 1페이지

- 한 번에 100장까지 인쇄할 수 있습니다.
- 신품은 **품목(행)당 1장**입니다. 수량이 5개여도 라벨은 1장이므로, 같은 상자·칸에 모아 두고 라벨을 붙이세요.
- 위치를 먼저 지정하고 인쇄하면 라벨에 위치 코드가 함께 찍힙니다.
- 외주 항목(사양 "외주")은 실물이 아니라서 목록에 나오지 않습니다.
- 라벨을 잃어버리면 라벨 조회 결과 화면의 **라벨 다시 인쇄**를 누릅니다.

## 4. 액정·보드 등 호환 부품

호환 부품은 두 가지를 따로 등록합니다.

- **부품 규격**: "이 부품이 무엇인가" (품번, 예: `LP140WF7-SPB1`) — 기기 마스터
- **재고 품목**: "선반에 실제로 있는 물건" — 재고 관리

둘을 **재고 연결**로 이어야 부품·기기 검색과 구매 가드에서 재고로 잡힙니다.

### 4.1 부품 규격 검색 · 생성

**관리자** — 기기 마스터 → 탭 **부품 규격**
1. "품번·별칭 검색"으로 먼저 찾아봅니다.
2. 없으면 **+ 새 부품 규격** → 부품 종류(필수: 액정, 배터리, 키보드, 칩/IC, 저장장치, 메모리, 메인보드, 케이블, 팬/쿨러, 케이스, 어댑터, 기타) · 품번/명칭(필수, 150자 이내) · 제조사(선택) → **등록**
3. 목록에서 규격을 누르면 대표 품번/명칭, 제조사, **호환 기준**(모델/변형 기준 또는 메인보드 기준), 호환 그룹, 설명, 별칭(품번·칩 마킹)을 고칠 수 있습니다.
   - 칩/IC는 자동으로 "메인보드 기준", 나머지는 "모델/변형 기준"으로 만들어집니다.

**고객서비스 외 직원** — 부품 규격 선택기("품번·칩 마킹으로 검색 (예: LP140WF7, BQ780)")에서 못 찾으면 **+ 새 부품 규격 등록**. 관리자 외에는 "검토 필요"로 등록됩니다.

### 4.2 수량 1개 품목으로 등록 ⚠

요청하신 "상태 · 테스트 여부 · 출처 · 위치를 넣어 수량 1개 품목으로 등록"하는 **전용 화면은 현재 없습니다.** 실제로 가능한 방법은 아래와 같습니다.

| 칸 | 지금 넣을 수 있는 곳 |
| --- | --- |
| 상태 | 신규 재고 등록의 **상태**(신품/중고품)만 있음 |
| 테스트 여부 | **칸 없음** — 재고 품목에는 저장할 곳이 없음 |
| 출처 | **칸 없음** — 재고 품목에는 저장할 곳이 없음 (적출·Donor 입고는 입출고 이력 메모에 "적출품 반환 입고"와 원 접수번호가 남음) |
| 위치 | 등록 후 라벨 조회 화면에서 지정 (§1.3) |

**매장에 이미 있는 낱개 부품을 지금 등록하는 방법 (관리자·팀장)**

1. 재고 관리 → **+ 신규 등록**, 상태 **중고품**, 수량 **1**, 기초견적은 §8 규칙.
   구분이 되도록 **용량 / 인치수** 칸에 크기 등 식별 정보를 적습니다 (예: `14인치 FHD 30핀`).
2. 같은 분류·같은 용량·같은 상태 품목이 이미 있으면 중복으로 막힙니다.
   이 경우 **기존 품목의 수량을 늘리는 방식**(관리자 인라인 수정)으로만 넣을 수 있고, 그러면 라벨은 1장을 같이 씁니다. (검토 사항 A-3)
3. 라벨 인쇄 (§3-3) → 부품에 붙이기 → 위치 지정 (§1.3)
4. 관리자: §4.3 재고 연결

> 적출 부품(수리 중 떼어낸 부품)과 Donor에서 떼어낸 부품은 입고 승인 시 **자동으로 1개씩 별도 품목**(중고, 기초견적 0원)이 되고 품목마다 라벨이 따로 생깁니다 (§6.4, §10.5).

### 4.3 재고 연결 (관리자)

기기 마스터 → 탭 **재고 연결**

1. "카테고리·사양·제품명 거르기" 칸으로 품목을 찾습니다. **미연결만**을 켜면 아직 연결 안 된 것만 보입니다.
2. 각 줄 오른쪽 부품 규격 선택기에서 규격을 고르면 바로 저장됩니다 (수량·금액은 바뀌지 않음).

- 이 화면에는 라벨 코드가 나오지 않습니다. 같은 이름의 낱개 품목이 여러 줄이면 구분이 어렵습니다 (검토 사항 A-5).

### 4.4 호환 정보 입력 — "문서 근거" / "추정" 선택 기준 (관리자)

기기 마스터 → **부품 규격** → 규격 선택 → 오른쪽 **호환성** 아래 **근거 추가**

1. 호환 대상 선택: 호환 기준이 "모델/변형"이면 모델 선택기, "메인보드"이면 보드 선택기
2. **근거 종류** 선택 (아래 기준)
3. **호환 여부**: 호환 / 조건부 / 비호환
   - 조건부는 **제한사항** 필수 (예: "밝기 조절 불가", "브래킷 가공 필요")
4. 메모 (선택 — 고객 개인정보를 적지 마세요) → **근거 등록**

| 근거 종류 | 화면 표시 신뢰도 | 언제 고르나 |
| --- | --- | --- |
| **문서 근거** | 문서 근거 | 데이터시트, 서비스 매뉴얼, 제조사 호환표 등 **출처가 있는 경우**. **출처(문서명 또는 URL) 입력 필수** |
| **추정** | 추정 | 규격·커넥터·크기가 같아 보이는 등 **출처 없이 판단한 경우** |
| 실장 확인 | 검증됨 | **첫 등록 때는 고르지 마세요** (아래 설명) |
| 관리자 조정 | (신뢰도는 그대로) | 상태만 바로잡을 때. 조정 사유 필수. "검증됨"을 만들 수 없음 |

**"검증됨"은 실제로 기기에 장착해 확인한 경우에만 생깁니다.**
정상 경로는 수리 중 **접수건 상세 → 수리 기록 → 사용 부품 → 호환 확인**입니다 (§10.4).
관리자 화면에도 "실장 확인" 종류가 있어 여기서 고르면 "검증됨"이 되지만, 초기 재고 등록 때는 **실제 장착 확인이 없으므로 반드시 "문서 근거" 또는 "추정"을 고르세요.** (검토 사항 A-6)

- 근거는 수정·삭제가 아니라 **철회**만 됩니다 (근거 보기 → 철회, 사유 필수). 기록은 남습니다.
- 같은 호환 그룹의 다른 규격에 근거가 있으면 "호환 그룹 후보"로 보이지만 저장된 근거는 아닙니다.

## 5. 라벨 사진으로 AI 후보 만들기

메뉴 **AI 사진 인식** — 관리자 · 팀장 · 담당기사 · 정밀수리팀이 올릴 수 있습니다.

1. 사진 종류 선택: **부품 라벨·칩 마킹** / **메인보드 번호** / **기기 라벨**
2. 대상 선택 (필수): 부품 규격 / 메인보드 / 모델. **이미 등록된 대상**에 별칭을 붙이는 기능입니다.
   - 부품 규격·모델은 선택기에서 즉석 등록도 가능 (§2.2, §4.1). 보드는 관리자에게 등록 요청.
3. 사진 선택 (jpg, png, webp, heic · 10MB 이하). **사진은 외부 AI로 전송되니 고객 이름·전화번호·주소가 보이지 않게** 찍으세요.
4. **인식 요청** → 최대 1분 정도 걸립니다.
5. 결과: 읽은 번호가 **별칭 후보**로 올라가거나, 제외 사유(이미 등록됨 / 다른 대상의 별칭·번호 / 개인정보로 보여 제외 / 읽을 수 없음 등)가 표시됩니다.

**승인 (관리자만)** — 기기 마스터 → 탭 **AI 후보**에서 **승인** / **반려**
(호환 정보 후보는 **문서 근거로 승인** / **추정으로 승인** / **반려**)

- **관리자가 승인하기 전에는 아무것도 등록되지 않습니다.** 검색에도 나오지 않습니다.
- AI 사진 인식은 **별칭(품번·마킹·보드 번호·모델 번호)만** 후보로 만듭니다. 재고 품목·수량·Donor는 만들지 않습니다.
- AI 승인으로는 "검증됨"이 생기지 않습니다 (문서 근거 / 추정만).

## 6. 폐기 기기·매장 보관 기기를 Donor로 등록

Donor = 부품을 떼어 쓸 수 있도록 보관하는 기기입니다.

### 6.1 등록 가능한 기기 — 두 가지 길

| 기기 | 등록 방법 | 확인 체크 |
| --- | --- | --- |
| 고객이 맡겼다가 **폐기로 취소된 접수건**의 기기 | §6.2 **Donor로 전환** (대시보드) | 고객 소유권 포기 동의 확인 |
| **접수 기록이 없는** 매장 보관 기기 (부품용 매입, 출처 불명 장기 보관, 예전에 폐기 확인까지 끝난 기기 등) | §6.5 **+ 매장 보관 기기 등록** (Donor 기기 메뉴) | 회사 소유 확인 |

- **고객이 맡긴 기기를 §6.5로 등록하면 안 됩니다.** 접수건이 있는 기기는 반드시 §6.2로 전환하세요.
- 어느 길로 만들어도 적출 후보, 사진, 라벨, 위치, 적출 입고, 검색은 똑같이 쓰입니다 (§6.3 – §6.4).

### 6.2 Donor로 전환 (관리자·팀장)

**대시보드** → **폐기 기기 확인 대기** (취소 시 "폐기"를 고른 접수건이 표시됨)

1. 해당 줄에서 **Donor로 전환** (그냥 폐기하면 **확인 완료**)
2. 입력
   - 브랜드 (필수), 모델명, 태그/라벨 — 접수 정보가 미리 채워짐. 개인정보는 지우고 저장
   - 상태 메모 (예: 힌지 파손, 메인보드 정상)
   - 보관 위치 (예: DONOR 선반 1) — 글자 메모입니다. 라벨에 찍히는 위치 코드는 §6.4에서 따로 지정
3. **소유권 포기 확인 체크 (필수)**:
   > 고객이 기기 소유권 포기(폐기 위임)에 동의했음을 확인했습니다.

   체크하지 않으면 **Donor로 전환** 버튼이 눌리지 않습니다. 체크한 사람·시각이 Donor 상세에 기록됩니다.
4. **Donor로 전환** → `D-0001` 형식 번호가 생기고, 폐기 확인도 함께 처리됩니다.

- 수리 기록에서 "Donor유지"로 처리한 적출 부품은 자동으로 적출 후보로 옮겨집니다.

### 6.3 부위별 상태 — 적출 후보 부품

메뉴 **Donor 기기** → 기기 선택 → **적출 후보 부품** (관리자·팀장·담당기사·정밀수리팀)

1. "부품 (예: 액정 패널, RAM 8GB, 키보드)" · 수량 · **상태** 선택 · 부품 규격(선택) · 메모(선택)
2. **후보 추가**

| 상태 | 뜻 |
| --- | --- |
| 양호 | 작동 확인함 |
| 미확인 | 아직 확인 안 함 (기본값) |
| 불량 | 고장 확인 |

- 부품 규격을 연결해 두면 부품·기기 검색과 구매 가드에 "Donor 재고"로 잡힙니다.
- **기기 정보**(관리자·팀장): 브랜드, 모델명, 태그/라벨, 보관 상태(보관중 / 적출 완료 / 폐기), 보관 위치(메모), 상태 메모, 표준 모델, 메인보드 → **저장**
- **사진**: **사진 추가** (최대 12장). 삭제는 관리자·팀장만.

### 6.4 Donor 기기 QR 라벨과 위치 (관리자·팀장)

- 라벨: **라벨 인쇄** → **Donor 기기** 탭 → 선택 → 인쇄. 또는 Donor 상세의 **라벨 인쇄**. **기기당 1장**입니다.
- 위치 코드 지정: Donor 라벨을 **라벨 조회**로 연 뒤 **보관 위치 변경** (§1.3)

### 6.5 매장 보관 기기를 Donor로 등록 — 접수 기록 없음 (관리자·팀장)

메뉴 **Donor 기기** → 오른쪽 위 **+ 매장 보관 기기 등록** (화면 제목 "매장 보관 기기 등록")
버튼은 관리자·팀장에게만 보입니다.

| 칸 | 필수 | 설명 |
| --- | :-: | --- |
| 기기 종류 | ● | 노트북 / 데스크탑 / 서버 / 나스 / 기타저장장치 / 태블릿 |
| 브랜드 | ● | 50자 이내 (예: Lenovo) |
| 모델명 | | 예: 14ARH7 |
| 표준 모델 · 메인보드 | | 모델 선택기·보드 선택기 (§2). 연결해 두면 부품·기기 검색과 구매 가드에 잡힙니다 |
| 태그/라벨 | | 기기 라벨의 품번·시리얼 등 |
| 보관 위치 | | 미리 만든 위치 코드에서 선택 (§1.1). 나중에 라벨 조회에서 바꿀 수 있음 |
| 보관 메모 · 상태 메모 | | 예: 상태 메모 "액정 정상, 보드 불량" |
| **취득 경위** | ● | 300자 이내. 어떻게 회사 것이 되었는지 (예: "2023년 부품용 매입", "출처 불명 장기 보관", "옛 접수 R-2024-0012 폐기분") |
| 취득일 | | 모르면 비워 둡니다 |
| 취득가 (원) | | 모르면 비워 둡니다. 쉼표(50,000)도 됩니다. **기록용**이며 적출 부품의 기초견적에는 들어가지 않습니다 (적출 부품은 0원, §8) |

**회사 소유 확인 체크 (필수)**:
> 이 기기는 회사 소유이며 고객이 맡긴 기기가 아님을 확인했습니다.

체크하지 않거나 필수 칸이 비어 있으면 "회사 소유 기기임을 확인해 주세요.", "취득 경위를 입력해 주세요." 같은 안내가 나오고 등록되지 않습니다.

**등록** → `D-0001` 형식 번호가 생기고 Donor 상세 화면으로 이동합니다.

- Donor 상세 위쪽에 **출처: 매장 보관 · (취득 경위)** 와 **회사 소유 확인: (직원) · (시각)** 이 표시됩니다.
- Donor 상세의 노란 **회사 자산 정보 (매장 보관)** 칸에서 취득 경위·취득일·취득가를 고칠 수 있습니다 (관리자·팀장, **저장**). 취득 경위는 비울 수 없습니다.
- Donor 기기 목록에는 **매장 보관** 배지가 붙고, **전체 출처** 목록에서 "접수 폐기 전환 / 매장 보관"으로 거를 수 있습니다.
- 그다음 할 일은 접수 전환 Donor와 같습니다: 적출 후보 부품 추가 (§6.3) → 라벨 인쇄·위치 지정 (§6.4) → 필요할 때 적출 입고 (§10.5).
- 적출 입고하면 입출고 이력 메모에 원 접수번호 대신 **"적출품 반환 입고 · Donor D-번호"** 가 남습니다.
- 잘못 등록했으면 직접 지우려 하지 말고 관리자에게 알리세요. 쓸 수 없게 된 기기는 **기기 정보**의 보관 상태를 **폐기**로 바꿉니다.

## 7. 상태 미확인 부품

### 7.1 재고 품목 ⚠

재고 품목의 상태는 **신품 / 중고품** 두 가지뿐이고 "미확인"이나 "테스트 여부"를 적을 칸이 없습니다.
또 화면에서 등록 후 **상태(신품/중고품)를 바꾸는 기능도 없습니다** (관리자 인라인 수정은 용량·수량·기초견적만 가능).

지금 할 수 있는 방법:
- 테스트하지 않은 중고 부품은 **중고품**으로 등록하고, 라벨을 붙인 뒤 **"미확인" 칸(위치)을 따로 정해** 보관하세요. (예: 위치 `TEST-01`) 테스트 후 정상이면 라벨 조회 화면에서 **보관 위치 변경**으로 정상 칸으로 옮깁니다.
- 불량으로 확인되면 관리자에게 알려 수량을 0으로 조정합니다 (검토 사항 C).

### 7.2 Donor 적출 후보 부품

- 등록 시 상태 **미확인**(기본값)으로 둡니다.
- 나중에 **상태(양호/미확인/불량)를 고치는 버튼은 없습니다.** 바꾸려면 그 후보를 **삭제**하고 올바른 상태로 다시 **후보 추가**하세요 (입고 요청 중인 후보는 먼저 요청 취소).
- 쓸 수 없게 된 부품은 **사용 불가**, 다시 쓸 수 있으면 **적출 가능으로**.

### 9.2 위치별 재고 목록 ⚠

- **라벨 인쇄** 화면(관리자·팀장): "코드·품목·위치 검색" 칸에 위치 코드(예: `A-01`)를 넣으면 그 위치의 재고(또는 Donor) 목록과 위치 칸이 보입니다. 인쇄하지 않고 확인용으로 써도 됩니다.
- **재고 관리** 목록(관리자·팀장): 각 품목의 라벨 코드 옆에 `· A-01-04`처럼 위치가 표시됩니다. (검색칸은 위치 코드로는 거르지 않음)

### 10.1 접수 선조회 패널
신규 접수에서 표준 모델을 고르면, 그 모델의 호환 부품·재고·Donor·과거 사례·메모를 보여 줍니다. 보기 전용이며 접수 저장에는 영향이 없습니다.

### 10.2 부품 역검색
- **기기로 부품 찾기**: 표준 모델 또는 메인보드 선택 → **호환 부품**과 **기기 지식**
- **부품으로 기기 찾기**: 부품 규격(품번·칩 마킹·별칭) 선택 → 맞는 기기
- 순위: 과거 수리 사례 → 검증됨 → 재고 → Donor → 문서 근거 → 추정
- **재고 수량이 잡히려면** 재고 품목이 부품 규격에 연결(§4.3)되어 있고, 그 규격에 호환 근거(§4.4)가 있어야 합니다. Donor는 적출 후보에 부품 규격이 있어야 합니다.

### 10.3 구매 가드
- 재고가 0개인 품목을 자재로 고르면 "구매"로 요청됩니다(**자재구매요청**).
- 관리자가 **재고 분류 설정** 화면의 **구매 요청 시 내부 자원 확인**을 켰을 때만, 구매 요청 전에 대체 가능한 재고·Donor 부품을 보여 주고 **구매 사유 (필수)** 를 받습니다. 꺼져 있으면 창이 뜨지 않습니다 (기본값: 꺼짐).
- 구매 사유 기록은 관리자 메뉴 **구매 사유 보고서**에서 봅니다.

### 10.4 수리 종료 시 호환 결과 체크
수리 기록의 **사용 부품**에는 출고·구매 승인된 자재가 자동으로 나옵니다. 장착 후 **호환 확인** → 부품 규격 확인 → 결과 **정상동작 / 조건부 / 비호환 / 판단불가** 선택.
- 정상동작·조건부·비호환은 "실장 확인" 근거가 되어 그 부품의 신뢰도가 **검증됨**이 됩니다. 판단불가는 근거를 남기지 않습니다.
- 재고 품목이 부품 규격에 연결되어 있으면 규격이 미리 선택됩니다.
- 외주·소프트웨어 항목은 대상이 아닙니다.

### 10.5 Donor 적출
1. 기사·정밀수리팀: 후보 줄의 **입고 요청** → 카테고리 · 사양 · 제품명 (필수) · 용량(선택) 입력
2. 관리자·팀장: **대시보드** 또는 **재고 관리** 화면의 **Donor 적출 입고 대기** → **입고 승인**, 또는 Donor 상세에서 **적출 입고**
3. 결과: 수량만큼 **1개씩 별도 재고 품목**(중고, 기초견적 0원)이 생기고 각각 라벨 코드가 붙습니다 → 라벨 인쇄 → 위치 지정
- 보관중인 Donor 기기의 부품만 입고할 수 있습니다.
- 새 재고 품목에는 후보의 부품 규격이 **자동으로 연결되지 않습니다.** 관리자가 §4.3에서 연결해야 검색에 잡힙니다 (검토 사항 A-7).

### B. 일괄 등록(CSV)

- **현재 CSV 일괄 등록 기능은 없습니다.**
- 있는 것: (1) 재고 분류 설정의 분류 이름 여러 개 붙여넣기(`bulkAddCategories/Specs/Products`) — 재고 품목은 만들지 않음. (2) n8n용 `POST /api/inventory/webhook` — 공유 API 키 + service_role로 **한 건씩** 카테고리·사양·제품을 찾거나 만들고, 같은 제품·상태·용량 행이 있으면 수량을 더함, 기초견적 0, INBOUND 기록.
- 필요성: 신품 표준 부품이 수십~수백 행이면 수동 입력(1행당 7칸)은 시간이 많이 들고 오타가 생깁니다. 최초 1회성 작업이라 효과가 큽니다.
- 데이터 무결성 위험 (도입한다면 고려할 점):
  1. **분류 난립**: 이름 표기 차이("SSD" vs "저장장치", 공백·대소문자)로 새 카테고리·사양이 생김. 웹훅은 카테고리를 영문 대문자 코드(`SSD`, `DISPLAY` …)로 받아 기존 한글 카테고리("저장장치", "액정")와 다른 분류를 새로 만듦.
  2. **중복·합산**: 같은 파일을 두 번 올리면 수량이 두 배. 웹훅처럼 "있으면 더하기"면 재실행이 위험 → 행마다 고유 키·미리보기·전체 롤백 필요.
  3. **원자성**: 현재 수동 등록·웹훅은 품목 INSERT와 INBOUND 기록이 별도 문장(트랜잭션 아님). 일괄 처리 중 실패하면 일부만 들어감. 원칙 P7/R5에 따라 단일 트랜잭션 RPC여야 함.
  4. **권한 우회**: service_role 경로는 RLS를 우회 → 역할 확인을 함수 안에서 해야 함.
  5. **라벨 번호 소진**: 실패한 INSERT도 `inventory_label_seq`를 소비 → 라벨 번호 건너뜀(무해하지만 혼란).
  6. **기초견적 오입력**: 금액 열의 단위·쉼표 오류가 바로 자재비·순이익 통계에 반영됨 (C 참고).
- 결론: 도입한다면 별도 phase로 계획(미리보기 → 검증 → 단일 트랜잭션 → 결과 보고)이 필요합니다.

| 위치 변경·해제 | 라벨 조회 → 보관 위치 변경 | 관리자·팀장 | 위치 자체는 삭제 불가, 사용 중지만 |
| 부품 규격 연결 변경 | 기기 마스터 → 재고 연결 | 관리자 | — |
| 분류 이름 수정·삭제 | 재고 분류 설정 | 관리자 | 카테고리 삭제는 하위 사양·제품 CASCADE. 품목이 있으면 RESTRICT로 실패 |
| Donor 정보 수정 | Donor 상세 → 기기 정보 → 저장 | 관리자·팀장 | Donor 기기 삭제 기능 없음 (보관 상태 "폐기"로 변경) |
| Donor 후보 삭제 | 후보 줄 **삭제** | 관리자·팀장·기사·정밀수리팀 | 입고 요청 중이면 버튼 없음 |
| 근거 되돌리기 | 근거 **철회** | 관리자 | 삭제 불가, 이력 유지 |

권장: 초기 등록 기간에는 "직원은 삭제하지 않고 관리자에게 보고" 원칙. 삭제는 이력까지 지우므로 수량 0 조정을 우선 검토.

### D. 재고 등록이 기존 출고·원가 계산에 영향을 주는 지점

1. **출고/구매 자동 구분**: 자재를 고를 때 품목 수량이 0 이하면 `purchase`, 1 이상이면 `dispatch`로 요청됨 (`EstimateCard.tsx`, `AddMaterialCard.tsx`). 실제 재고보다 많이 등록하면 출고 요청이 승인되며 없는 재고가 차감되고, 0으로 등록하면 구매로 흘러감.
2. **출고 승인 시 차감**: `approve_material_dispatch`가 `inventory_items.quantity`를 잠그고 차감, OUTBOUND 기록. 수량이 부족하면 "재고 부족"으로 실패.
3. **자재비 = 현재 기초견적**: `recalc_ticket_material_cost`는 `COALESCE(override_unit_price, inventory_items.base_estimate) × 수량`을 **재계산 시점의** 기초견적으로 계산 (스냅샷 아님). 재계산은 자재 추가·수정, 출고 승인 이후 흐름, 반품 확인, **완료 건 수동 비용 추가·수정**(`add/update_ticket_manual_cost`) 때 일어남. → 이미 쓰인 품목의 기초견적을 나중에 바꾸면, 그 접수건에서 재계산이 일어날 때(완료 건 포함) 자재비가 바뀌고 **통계(순이익)도 바뀜** (`statisticsActions.ts`는 `material_cost` 사용).
4. **기초견적 0원**: 매입가 미상·적출품은 자재비 0 → 해당 수리의 순이익이 실제보다 크게 집계됨 (기존 적출품 규칙과 동일한 한계).
5. **환불**: `request_refund` / `apply_refund_material_adjustments`도 `override_unit_price` 또는 `base_estimate`를 단가로 사용.
6. **출고 승인 위젯·견적 표시**: 대시보드·재고 관리의 출고 요청 위젯과 견적 카드가 `base_estimate × 수량`을 표시.
7. **구매 가드**: 등록한 재고(수량 > 0, 외주 제외)가 같은 품목·같은 제품+용량·같은 부품 규격·호환 규격 순으로 "대체 자원"이 되어, 가드가 켜져 있으면 구매 사유 입력을 요구하게 됨.
8. **변경 없는 부분**: 재고 등록 자체는 기존 접수건의 `material_cost`를 즉시 바꾸지 않음 (재계산 때만 반영). 라벨 코드·보관 위치·부품 규격 연결은 원가 계산에 쓰이지 않음.
